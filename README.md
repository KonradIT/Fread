## Features added

### Auto-generated alt-text in images using OpenRouter

This feature is inspired by [this post](https://bsky.app/profile/ed3d.net/post/3mkvxlhyot22i) and by [Ave's blog post](https://ave.zone/blog/playing-with-vlm-generated-alt-text).

A new button shows up on the alt-text dialog to send the image to an LLM which returns the alt text. The model prompt, model choice and max token size were taken from Ave's blog post as-is.

A new config page was added to the settings to configure LLM autogenerated alt-text. After it is filled out with your LLM provider of choice (using OpenAI-compatible API requests; openrouter is just one choice), the button appears when composing a post with an image attached.

The iOS part is stubbed-out; WIP work is on the [`ai-autogenerate-alt-text-ios`](https://github.com/KonradIT/Fread/tree/ai-autogenerate-alt-text-ios) branch.

### Add ability to translate posts

Adds an option to translate posts via the 3-dot menu on Bluesky posts.

On Android, this uses the `ACTION_PROCESS_TEXT` intent which shows a list of appropriate apps that can translate text (Google Translate included). On iOS, the text is shared and the user picks the translation app.

The Mastodon/ActivityPub flow is left intact.

### Fix for article rich metadata not being populated

- `sharedHttpClient` had no `User-Agent` header — fixed, along with content-type. Use a Chrome user agent and the `Accept: text/html` header so websites send back their og:xxxxx tags.
- Use Bluesky's existing infra to populate rich metadata: `https://cardyb.bsky.app/v1/extract?url=$website` returns a JSON-formatted response with the data — this is what bluesky-social uses. Falls back to the existing logic.
